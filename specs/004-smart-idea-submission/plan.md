# Implementation Plan: Smart Idea Submission Forms

**Branch**: `004-add-smart-idea-forms` | **Date**: 2026-05-14 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/004-smart-idea-submission/spec.md`

## Summary

Implement category-driven smart submission forms by extending the existing idea submission flow with an admin-managed dynamic field-rule model. The selected category determines additional rendered inputs and server-side validation rules. Submitted dynamic values are stored as per-idea key/value records linked to field rules, with reviewer-visible detail rendering. Event Plan support is seeded in v1 with optional `planned_date` and `planned_attendees` fields. Admin-only rule management is enforced server-side, no new npm dependencies are added, and test-project rollout permits DB reset without historical migration.

## Technical Context

**Language/Version**: TypeScript 5.9 (strict mode)

**Primary Dependencies**: Next.js 15 (App Router), React 19, Drizzle ORM 0.45, Zod 4, react-hook-form 7, iron-session 8, Tailwind CSS 4, shadcn/ui

**Storage**: SQLite via better-sqlite3 + Drizzle ORM; new tables `idea_category_field_rules` and `idea_field_values`

**Testing**: Vitest + React Testing Library (unit/component), integration tests under `tests/integration`, Playwright for E2E

**Target Platform**: Web application (Node.js server + browser clients)

**Project Type**: Single Next.js full-stack application

**Performance Goals**: Dynamic rules load and form update in under 300 ms after category selection; successful submission round-trip in under 2 s in local/dev environment

**Constraints**: No new dependencies; Tailwind-only styling; admin-only rule-management operations; DB reset acceptable for v1 test project; strict server-side validation for shared and dynamic fields

**Scale/Scope**: Single test project deployment; low concurrent usage; one selected category per submission; initial field types limited to text/number/date
